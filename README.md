# Sparse Branch Machine Research

CPU-first sparse learning research platform.  The machine uses bounded content
addressing, sparse branch edges, persistent local state and local updates rather
than dense global matrix layers or backpropagation through a fixed network.

## Primary task: mathematical token cross-entropy

The primary task now uses the same training contract as tokenizer-based sequence
training:

```text
input token x_t -> predict categorical distribution p(x_{t+1} | history)
loss            -> -log p(target token)
```

It is not a language corpus.  Tokens are generated by a fully auditable
mathematical autoregressive process.  The true distribution combines lag-1,
lag-2 and lag-4 circular components plus a weaker nonlinear interaction term.
The next token is sampled from that distribution, so the task has irreducible
uncertainty and cannot reach artificial 99% accuracy by memorizing a deterministic
recurrence.

Default calibration:

- vocabulary: 32 token IDs;
- 64 independent sequences;
- 2,048 tokens per sequence;
- 80,000 training examples, then strict frozen evaluation;
- objective: exact categorical cross-entropy;
- metrics: NLL, bits/token, perplexity, top-1/top-5 and target probability;
- oracle NLL: recorded by the mathematical generator.

On the theory-alignment branch the default topology starts from lag 1 and
learns which additional address channels survive. Across seeds 7, 11 and 19 it
obtains mean frozen NLL 3.41847 and finishes with learned lags `[1,2]`. A fixed
`[1,2,4]` control obtains 3.41132, the unigram baseline is about 3.466 and the
generator oracle about 2.914. The unresolved gap is retained deliberately.

## Tokenizer alignment

External token IDs can be passed directly without changing the model API:

```python
from sbm_runtime import Runtime

runtime = Runtime("build/libsbm_api.so")
ids = [101, 2074, 2003, 1037, 3231, 102]
offsets = [0, len(ids)]

with runtime.token_dataset_from_ids(ids, vocab_size=30_522,
                                    sequence_offsets=offsets) as dataset:
    with runtime.config() as config:
        result = dataset.run(config, warmup=4)
```

The runtime treats sequence offsets as document boundaries.  At a boundary it
clears transient token history, the previous route and delayed trace credit, but
retains learned nodes and edges.  This prevents unrelated documents from being
silently concatenated.

The current dense local logit vector is suitable for synthetic and moderate
vocabularies.  A large 30k–100k vocabulary is API-compatible but not yet memory-
efficient; hierarchical or sampled output normalization remains future work.

## Retained vector objective

The previous continuous-vector mathematical task remains available as
`--task vector`.  It is useful for regression experiments and SIMD validation.
The dataset handle and experiment API dispatch automatically by dataset kind.

## Adaptive sparse token learning

Each active node stores a local logit vector. The model begins with a seed
address topology, normally lag 1. Additional temporal channels are proposed at
runtime, locally adapted, frozen for a validation tail and accepted only when
exact channel ablation improves cross-entropy.

```text
seed channel -> propose lag -> adapt local nodes -> freeze candidate
             -> ablate whole channel -> accept or erase
```

Accepted channels contribute additive logits. Exact-address nodes receive local
cross-entropy gradients; nodes recalled through foreign control edges remain
read-only. Accepted non-seed channels are audited continuously and can later be
retired if their sustained counterfactual contribution becomes negative.

All topology decisions are emitted in result JSON. See `THEORY_ALIGNMENT.md`.

## Shared-library interface

```text
sbm_core -> sbm_machine / sbm_dataset -> sbm_experiment -> sbm_api
                                                        -> sbm_cli
                                                        -> Python ctypes
```

`sbm_api` exposes a versioned C ABI with opaque configuration and dataset
handles.  The CLI links only the API library.  Python calls the same library
in-process, including construction from externally tokenized IDs.

Build and test:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

Run the mathematical token task:

```bash
./build/sbm_cli \
  --task token-ce \
  --sequences 64 \
  --sequence-length 2048 \
  --vocab-size 32 \
  --warmup 80000 \
  --output results.json
```

Run the retained vector task:

```bash
./build/sbm_cli --task vector --length 120000 --warmup 40000
```

## Automated calibration

All model parameters are exposed through `sbm_parameter_schema_json()`.  Schema
entries identify whether they apply to `token-ce`, `vector`, or both.  The tuner
filters the search space by task and always includes the unmodified default
configuration as a control candidate.

```bash
python scripts/tune.py \
  --library build/libsbm_api.so \
  --task token-ce \
  --trials 27 \
  --seeds 7,11,19 \
  --jobs 3 \
  --best-config best_token_config.json
```

For token training the objective is minimum mean frozen cross-entropy; for vector
training it remains maximum frozen R2.  Repeated manual parameter edits are not
part of the accepted workflow.

## Current limits

- Local token output is still a dense vector over the vocabulary.
- Proposal generation still enumerates temporal lags; arbitrary address
  programs are not yet synthesized.
- The adaptive topology currently retains `[1,2]` and remains weaker than the
  fixed `[1,2,4]` control on the present task.
- Control edges carry routing credit only; they do not yet transform logits.
- Formal tokenizer ID ingestion is implemented, but corpus streaming, sharding,
  masking and distributed checkpointing are not yet present.
